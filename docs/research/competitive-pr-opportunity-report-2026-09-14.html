Detailed notes

How the best ideas should land.

The transferable value is usually a behavioral contract and a failure model—not the exact component tree or storage format used by a competitor.

P0Export

Deterministic thread export

Borrow

  • Thread action in header/sidebar; no provider API call.
  • Metadata header, role-labeled messages, safe filename, local save.
  • Pure serializer with snapshot/unit coverage.

Improve for Ryco

  • Include provider instance, model, timestamps, worktree/branch, and linked work items.
  • Condense tool calls and approvals rather than dumping raw event payloads.
  • Make output stable across live replay and paginated history.

Evidence

T3 #11726; Ryco feature spec already present.

P0Editor

Autosave without losing trust

Borrow

  • Save after roughly 400 ms idle; share one draft across preview/full/diff editors.
  • Drain in-flight writes before file/page navigation and prompt submission.
  • Pause automatic retry after conflicts; keep the user’s draft intact.

Ryco substrate

PreviewFileEditSession.ts already tracks saved contents, file version, encoding, line endings, saving/error/conflict states, reload, and discard. That makes this an extension rather than a rewrite.

Guardrails

Separate Reload, Discard, and Overwrite; never silently overwrite after a disk version mismatch.

P1Review

Review should answer “what changed, why, and against what?”

Synara’s merged #561 and T3’s active #11256 converge on a richer review workspace. The right Ryco cut is smaller than either combined PR.

Phase A: performance and navigation

  • Key parsed files by their own patch segment so an edit in one file does not remount all files.
  • Add next/previous changed-file commands, visible-file synchronization, and gutter markers.
  • Enable word-level intra-line highlights where Pierre supports them.

Phase B: investigation

  • Compare working tree with an arbitrary branch or commit, using merge-base for branch comparisons.
  • Click a supported diff line to request blame against the displayed base.
  • Remember comparison scope per repository, not globally.

Phase C: staging

  • Review Staged and Unstaged independently.
  • Stage files or hunks only after stale index/HEAD/branch checks.
  • Keep later agent edits visible against the index.

Do not duplicate

  • GitHub viewed-state is already shipped across Ryco web/mobile/server.
  • Occurrence search and click-to-editor already exist.
  • Basic in-app editing and version conflicts already exist.
P1Worktrees

Configurable roots must remain policy-bound.

  • Environment default; optional project override; reset means inherit.
  • Expand ~/ server-side and canonicalize before validation.
  • Existing worktrees stay registered after a preference change.
  • Explicit checkout paths continue to win for imported/adopted worktrees.
  • In restricted mode, reject paths outside workspaceAccessRoot; never let a setting bypass hosted mutation ownership.

Local delta

Ryco currently exposes app-managed or project-metadata worktree placement, not a user-selected base directory.

P1Terminal

Benchmark the terminal before changing it.

Ryco already has byte/line-bounded scrollback, a 2 MiB history ceiling, persisted terminal logs, and bounded pending process output. T3 #9027 is still valuable as a test matrix.

  • Slow WebSocket/client cannot grow an unbounded queue.
  • PTY pauses and resumes without losing exit ordering.
  • Extended history is requested incrementally rather than sent on every attach.
  • Replay plus new live bytes remain ordered across resets and reconnects.
  • Alternate-screen/DEC modes restore after compaction and server restart.
P2Memory

Project memory needs explicit curation.

Synara #1148 is the strongest active product bet: 60 commits, clean merge state, and a bounded service design. The attractive parts are typed memory, decay, provenance, pin/affirm/forget, FTS, idempotent receipts, and poison-row isolation.

Ryco conditions

  • Opt-in per project and provider-neutral.
  • Never ingest credentials, raw tool outputs, hidden instructions, or private Hub metadata.
  • Show exactly what was recalled into a turn.
  • Bound write size, row count, recall count, and maintenance work.
  • Support export and complete deletion before automatic memory is enabled.
P2Scheduling

Automations are an orchestration feature, not a timer UI.

Poracode #583 proposes cron, heartbeat, completion policies, persisted results, MCP/IPC/ remote/mobile control, and unread/archive/retry triage. Synara has already shipped exact provider/model selection for agent-authored automations.

  • Persist logical run identity and receipts before dispatch.
  • Revalidate provider availability, model options, workspace, and mutation lease at run time.
  • Separate recurring heartbeat follow-up from standalone scheduled work.
  • Skip/quarantine corrupt rows instead of stopping the scheduler.
  • Surface only actionable changes by default; unchanged monitors should stay quiet.
P1Onboarding

Guide first use without conflating trust setup.

Synara #1031 covers provider discovery, inline sign-in, theme, project creation, and a feature tour. Ryco should keep its security-critical Hub/native trust flows authoritative and separate, while adding a short product onboarding for desktop/local web.

  • Detect installed providers and show live auth/version status.
  • Offer project creation/drop before landing in an empty shell.
  • Allow replay from Settings.
  • Persist completion locally first; do not let a server reset unexpectedly reopen it.

Stacked PRs

Review the layers, not cumulative diffs.

The most explicit stack is Synara’s Linux computer-control series. T3 also has a large orchestrator root with dependent branches, plus feature stacks that intentionally target main with cumulative diffs.

Synara Linux computer control

The authors state the merge order directly. Each PR targets main, so GitHub’s ordinary diff includes its unmerged prerequisites; use the linked compare range in each PR body to isolate the layer.

#820 transport → #821 approvals → #822 core/leases → #823 KWin → #824 nested KWin → #780 Hyprland
  • Best Ryco value: compositor discovery, exact prebuild matching, exclusive ownership, per-session tokens, human-input guards, provision locks, cancellation, and stale-credential rejection.
  • Do not copy the architecture wholesale: Ryco already has a native helper, leases, approval UX, browser bridge, cursor, and emergency stop.
  • Optional macOS branch #1010 branches after the shared core and can be reviewed independently of the Linux backends.

T3 orchestration v2 and dependent work

#2829 is the 1,242-file root. Active children target feature branches—for example scheduled-row quarantine #11585 targets t3code/codex-turn-mapping, and several Swift parity PRs target the Swift rebuild branch.

  • Relevant patterns: provider-neutral event ingestion, receipts/replay, startup settlement, bounded projections, and ownership held until cleanup finishes.
  • Not a direct Ryco port: Ryco already has an Effect-based orchestration engine and provider runtime ingestion boundary.
  • Use individual leaf PRs as adversarial tests against Ryco rather than treating the root diff as an implementation guide.

T3 review and presentation stacks

T3 #11256 is itself an integration PR for a native GitHub stack. Earlier inline-context work explicitly listed a review order before the merged #11265 umbrella.

  • Take the review feature in separable slices: cache/navigation, compare/blame, then staging/commit.
  • Keep structured context canonical across draft, queue, attachment upload, handoff, and older-server fallback.
  • Do not accept a giant cumulative diff just because the final behavior is attractive.

Open release notes

Reliability audits extracted from merged work

Provider and interaction lifecycle

  • Duplicate approval clicks/keys converge on one durable decision; an already-answered server race triggers refresh, not a raw invariant.
  • Pending user questions become explicitly recoverable or expired after provider restart; dead callbacks must not remain answerable.
  • Stopped OpenCode contexts must report inactive so session recovery can run.
  • Provider handoff preserves target provider settings and bounds imported history to its context window.

Packaging and updates

  • Build the production bundles, enumerate emitted runtime externals, and validate the clean installer stage in ordinary CI.
  • Do not let package managers prune native dependencies shipped inside platform packages.
  • Preserve legacy launcher entry points across self-update transitions.
  • Filter preview-only releases out of nightly changelog presentation.

Cross-platform details

  • Parse version output with optional v prefixes.
  • Discover version-manager Node paths before WSL provider launch.
  • Avoid JS methods absent from the shipped Hermes runtime.
  • Do not expose a whole single pane as disabled through a drag library’s ARIA activator fallback.

Ryco-specific caution

  • Generic reconnect helpers must never race hosted lifecycle revalidation.
  • Provider/client recovery must not publish readiness from a stale environment, selection, or generation.
  • Computer-use/browser credentials and captured documents stay outside ordinary transcript and diagnostic persistence.

Computer use

Subagents and peer work

In-app editing

Remote and hosted lifecycle

Cross-node workspace, relay, E2EE, passkeys, node selection, and mutation-readiness rules are more security-sensitive than generic reconnect patterns elsewhere.
