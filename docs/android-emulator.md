# Android emulator adapter

The Simulator pane can discover and attach Android virtual devices on macOS, Linux and Windows. Install Android SDK Platform-Tools and Android Emulator, then create an AVD with a compatible system image in Android Studio's Device Manager. Ryco uses `ANDROID_HOME`, then `ANDROID_SDK_ROOT`, standard SDK locations, or executables on PATH. SDK Build-Tools (`aapt`) are also needed to identify the package in an APK before installation. Missing tools and missing AVDs produce setup instructions; installing or downloading SDK components remains a user action.

Missing pieces are named precisely: the package to install for platform-tools, the emulator or the command-line tools, and, when no AVD exists, an `avdmanager create avd` command for a system image that is already installed.

Select an AVD in the existing pane. Ryco boots stopped AVDs headlessly, waits for Android's boot-completed property, and confirms a screenshot before completing attachment. AVDs have stable `android:<avd-name>` IDs; transient adb serials are resolved at operation time. Commands pin adb transport IDs so a reused emulator port cannot redirect an in-flight action to a different device. Keyboard input keeps its transport identity across sequential RPCs until detach or shutdown. A transport change or input failure cancels the queued suffix; detach and reattach before retrying. Physical devices, network adb targets and multiple simultaneous instances of the same AVD are outside this adapter's scope. Offline or ambiguous emulator targets refuse control.

### Video and input

Android streams H.264 into the same frame socket, WebCodecs viewer, keyframe priming and per-viewer drop control as iOS. The source is scrcpy-server v5.0.1 (Apache-2.0, see THIRD_PARTY_NOTICES.md), downloaded once from its GitHub release, checked against a pinned SHA-256 and cached in `<Ryco home>/cache/android/scrcpy`. Ryco pushes it to `/data/local/tmp`, opens an `adb forward` tunnel to its abstract socket (the host never listens for the device) and runs two sessions per emulator:

- a **control session** without video for all input: live touch down, move and up, taps, swipes (held still before lifting, so lists stop where the finger did), keycodes with modifiers, text (ASCII through key events, anything else through the clipboard), paste, Back, Home, Recents, Lock, volume and rotation. It starts on first input and closes after two idle minutes, a restart of the emulator or detach.
- a **video session** while a pane watches: H.264 Baseline capped at 1600 px on the long side and 60 fps. A resync asks the encoder for a fresh keyframe (`RESET_VIDEO`) instead of restarting the stream.

The descriptor's `preview` field tells the pane which path a device uses. It is `video` once scrcpy streams and `screenshots` when it cannot (no network for the first download, a server that will not start). In that case the pane keeps the old PNG sampler and input falls back to `adb shell input`. `RYCO_ANDROID_SCRCPY=0` forces that fallback on a node. Points are display pixels. The geometry follows rotation from the stream, and the pane maps a smaller video frame back to display pixels.

### Agents

- **Tree:** `describe_ui`, refs, label and role targeting, settle detection and diffs work as on iOS. The tree comes from Ryco's own resident UI reader, a small Java class in `apps/server/src/device/android/androidUiHelperSource.ts`. It is compiled on first use with the SDK's newest platform `android.jar` (API 30+), d8 from build-tools and a JDK (`JAVA_HOME`, macOS `java_home`, or Android Studio's JBR), and cached by source hash. It runs through `app_process` with the system `uiautomator.jar` wrapper, taking about 2 ms per read instead of `uiautomator dump`'s 2 s. Without a JDK it falls back to `uiautomator dump`. It exits after 30 idle seconds, because Android allows one UiAutomation client at a time. Widget classes map to the iOS role names, and a clickable row folds its title and subtitle into one labelled element.
- **Logs:** `device_logs` reads logcat (main, system and crash buffers) for the package's processes, including ones that died in the window. Crashes summarize `FATAL EXCEPTION` blocks, native tombstones and ANRs.
- **Settings:** `device_configure` supports appearance (`cmd uimode`), text size (`font_scale`), location (emulator console `geo fix`), runtime permissions (`pm grant/revoke`, plus clearing the user flags for reset), orientation and network on/off (Wi-Fi and mobile data). Push and clearing the location have no Android equivalent and are refused.
- **Coordinates after a rotation:** agents give x/y in the upright screen they see in screenshots and the tree, on both platforms. A turned iOS simulator keeps its touch input in portrait points, so the manager maps agent and tree points back through the recorded orientation (`DeviceManager.toInputPoint`). Android's video, tree and input all turn with the display (`uprightFrames`), so the manager tracks no orientation for it, and the pane never rotates its chassis.
- **Recording:** recording uses `screenrecord`. The MP4 lands next to iOS recordings. screenrecord stops a file after three minutes.

## Ownership and authorization

`PlatformDeviceBackend` routes iOS and Android operations into one `DeviceManager`. The shared global boot cap, thread attachment rules, idle shutdown, persistent boot ownership and process-exit cleanup remain authoritative. User-started emulators remain user-owned and are not stopped by Ryco disposal. Failed launches kill only the process started by that attempt. A transient discovery failure retains the platform's last observation so a missing SDK response cannot silently discard boot ownership; actual control and attachment still validate with the SDK.

The adapter adds no RPC methods, relay connections or authorization decisions. Agent Control installs still require an approved workspace-contained artifact, now either `.app` or `.apk`; canonical-path and symlink-escape checks run through the existing policy. The frozen web phone tier and shared client-runtime lifecycle are unchanged. iOS continues using its native helper and video transport.

## Upstream verification

Reviewed the [v0.0.37 release](https://github.com/pingdotgg/t3code/releases/tag/v0.0.37) as the requested baseline and recent [v0.0.41 nightly releases](https://github.com/pingdotgg/t3code/releases/tag/v0.0.41-nightly.20260911.1564). The [nightly device guide](https://github.com/pingdotgg/t3code/blob/v0.0.41-nightly.20260911.1564/docs/user/devices.md) and [LocalDeviceHost source](https://github.com/pingdotgg/t3code/blob/v0.0.41-nightly.20260911.1564/apps/server/src/device/LocalDeviceHost.ts) confirm Android SDK detection and delegation to expo-device-hub/agent-device. The [earlier September 11 nightly guide](https://github.com/pingdotgg/t3code/blob/v0.0.41-nightly.20260911.1551/docs/user/devices.md) is a second pinned comparison.

Upstream's guide says devices keep running when its helper processes stop; importing that behavior would conflict with Ryco's boot ownership policy. This implementation instead adapts the public [Android emulator CLI](https://developer.android.com/studio/run/emulator-commandline) and [adb](https://developer.android.com/tools/adb) into Ryco's existing backend interface. Upstream's [MIT license](https://github.com/pingdotgg/t3code/blob/v0.0.41-nightly.20260911.1564/LICENSE) was inspected before reading implementation references. No upstream implementation code or helper packages were copied.

## Integration and validation

The shared touch points are device/Agent Control contracts, the device service layer, the pane's preview and input selection, and install-artifact policy/tool descriptions. Coordinate these files with the multi-device/SSH and iOS-control workstreams. The router is platform dispatch for one existing device manager, not a second host or multi-stream manager.

Focused tests cover missing tools/AVDs, offline and ambiguous targets, boot deduplication and failure cleanup, boot ownership across a transient SDK failure, cross-platform boot limits, binary command timeout/failure, remote-shell quoting, screenshot validation, HID mapping, APK metadata/install failures, and approved artifact traversal/symlink rejection. Existing iOS device, gateway authorization and contracts tests remain part of the affected checks. Windows/Linux adapters are covered by command/path logic and typechecking; native host smoke testing is still needed on those operating systems.

A macOS smoke test against an installed API 34 AVD passed discovery, manager-owned cold boot, display attachment, a 2560×1600 PNG capture, Home/Back input, launch of the installed Settings app, and manager disposal. APK installation is validated with command fixtures; a signed APK install remains follow-up qualification. Focused Chromium coverage checks PNG preview and coordinate input, Android controls, ordered text/Backspace/Enter, cancellation after targeting failure, detach and reconnect, and first-time iOS helper setup. Backend regressions cover sequential RPCs across an AVD transport change and explicit reattachment recovery.
