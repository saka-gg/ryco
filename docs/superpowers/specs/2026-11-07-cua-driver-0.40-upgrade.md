# Cua driver 0.40.1 upgrade (Computer Use phase 5)

Status: implemented on branch `computer-use/5-cua-upgrade`; not yet live-tested in the desktop app (see Testing).

## Goal

Move Ryco's macOS Computer Use engine from upstream Cua driver 0.28.2 plus Synara's native patch
(revision 40) to upstream cua-driver 0.40.1, so Ryco gets upstream's background work: background
drag, background menus and dropdowns without raising the window, no focus bounce, page reads on
another Space, recovery hints, pointer-free window screenshots, safer web typing retry advice,
region-painted cursor overlay, the macOS 27 window-local click fix, JPEG window state and the
refusal of disabled controls. Ryco's own safety layer (input admission, cancellation, exact
targets) and its driver protocol stay.

## Why this is a port, not a bump

Upstream changed about 315k lines of the driver between the two versions. Plain 0.40.1 cannot run
Ryco: its tool schemas are closed now (unknown arguments are refused with `invalid_arguments`), and
Ryco sends patch-only arguments on every pointer call. The Stop and Escape guarantees, the exact-target
checks, clipboard preservation and seven tools Ryco calls exist only in the patch. A trial
cherry-pick of the patch onto 0.40.1 conflicted in 44 files (about 250 regions), concentrated in
the macOS crate.

The patch therefore becomes Ryco-owned: rebased onto 0.40.1 feature by feature, dropping what
upstream now does itself. It stays MIT, keeps the Synara and Cua notices, and the README in
`apps/desktop/patches/cua-driver/` records what Ryco changed.

### Background keyboard shortcuts

The live test found that Shift+Cmd+T in a background TextEdit window had no effect. Cause: the patch
sent the chord as one authenticated key event to the process, which reaches the window's views but
never the app's menu key equivalents, and an inactive app has no key window. Shift+Cmd+T is a menu
shortcut (Format > Make Plain Text), so nothing handled it while the result said "Pressed".
Upstream 0.35.3 and 0.36 fixed this: `hotkey` finds the menu item that owns the shortcut and presses
it through accessibility, after making the addressed window key without raising it. The port uses
that route and keeps the patch's admission and target checks around it.

## Protocol changes for Ryco

The driver protocol Ryco speaks stays the same: socket framing, handshake, `cancel_input`,
`expected_input_epoch`, refusal codes, the extra tools and arguments, and the stderr status lines.
Changes:

- `nativeRevision` 41. The host already retires a daemon whose revision differs, so a 0.28-based
  binary can never pass.
- `set_value` no longer takes `element_index` upstream; Ryco's web text path sends only the token.
- The host no longer sets `SYNARA_CUA_{FOREGROUND,BACKGROUND}_OBSERVATION_MS`.
- The host strips inherited `CUA_DRIVER_*` and `SYNARA_CUA_*` variables from the driver's
  environment (upstream reads many: fast path, brief foreground drags, key gaps) and sets
  `DO_NOT_TRACK=1`.
- Pane stills pass `display_only: true`, so a preview read never changes the window's pixel frame.
- Element tokens: a new tree read of a window replaces that window's snapshot, as in 0.28.

## Build

- The toolchain stays at Rust 1.97.1.
- Since 0.39 the driver links `libs/cua/crates/cua-telemetry`, which inherits `libs/cua`'s workspace
  manifest and embeds two JSON files. The provisioner now archives those paths with
  `libs/cua-driver`.
- An unpatched 0.40.1 release build takes about 3 minutes on an M-series Mac.

## Fixes found while porting

- **Driver crash while typing.** Upstream 0.40 reads the keyboard layout (for layout-aware keys, #6659)
  on a worker thread. On macOS 27 the Text Input Source API asserts the main queue and the driver dies
  with SIGTRAP mid-call; the caller only sees a timeout. Pristine 0.40.1 crashes the same way. The port
  reads the layout on AppKit's main queue (500 ms bound, US map as fallback).
- **Background menus on a non-key window.** Upstream refuses a background `invoke_menu` unless the
  addressed window is already the app's main and focused window, while its `hotkey` menu route first
  makes the window key without raising it. The port gives `invoke_menu` the same step, so menus work on
  any document window of a background app; the sibling-window refusal still applies when that fails.

## Testing

- Driver crates: contract 67, core 1246, cursor-overlay 186, platform-macos 777, cua-driver 365 unit tests
  pass. Both patches apply to the pinned source with `patch` and `git apply`, and reproduce the port tree
  byte for byte.
- Ryco: `bun run check`, `bun run check:changed --tests=affected` (only the known local failures
  `ProjectionPipeline.followUpQueue` and `Migrations/026`), `bun run build:desktop` (fetches the pinned
  commit from GitHub and builds the patched driver), `bun run release:smoke`, and the native smoke
  (`computer-use-native-smoke.ts`, which drives Ryco's Swift helper) pass.
- Live, against the provisioned binary through a minimal embedded host (the same handshake, epoch and
  socket protocol as `cuaDriverHost.ts`; the dev desktop app could not run because another session's
  dev app held the single-instance lock):
  - background semantic typing and key typing into TextEdit, confirmed by read-back;
  - Shift+Cmd+T in a background TextEdit window: the driver pressed Format > Make Plain Text through
    accessibility, TextEdit's confirmation sheet appeared, OK was pressed in the background and the
    format bar disappeared;
  - background menus on a non-key window (Edit > Select All, Format > Font > Bold) and a format-bar
    dropdown (font family) set by opening and closing its popup; window order unchanged;
  - background pixel clicks in Calculator (window points): 56×7, 123×4 computed correctly;
  - two sessions in parallel: TextEdit typing 6/6 lines while Calculator computed 43×21, 5.7 s;
  - background drag reaches the window (caret moves), as upstream; neither build drag-selects text in
    TextEdit or moves an unbundled test slider, so drags are not further qualified.
- Not verified: the full desktop app (consent dialogs, preview, menu bar status, Stop/Escape against a
  live driver), Chromium/Electron targets, the browser tools against a real browser, Linux (0002 is not
  compiled here).

## Risks

- Size: the port touches most of the macOS crate. Unit tests and the native smoke cover the
  mechanics, not every app. Live testing covers TextEdit, a browser and two chats in parallel.
- Divergent policies (background click activation, Chromium primer) keep Ryco's current behavior;
  if upstream's recipe makes more background clicks land, that is a follow-up decision.
- The embedded driver still reads `~/.cua-driver/config.json` for some cursor options; Ryco forces
  the options it relies on.
- PR CI does not build the patched driver; the first CI build is the release job. Local provisioner
  builds and `git apply --check` gate the patch.
