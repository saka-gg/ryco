## Protocol double-check

- [Codex App Server](https://learn.chatgpt.com/docs/app-server): use native thread/item/turn notifications and the installed protocol schemas. Ryco's `CodexSessionRuntime.ts` already tracks collaboration children, separates their events from the root, and synthesizes lifecycle/usage events. There is no justification for replacing that with tool-title guessing.
- [Claude SDK subagents](https://code.claude.com/docs/en/agent-sdk/subagents): preserve parent tool linkage. Ryco already captures task lifecycle, tool attribution, workflow phase/member state, model observations, usage, and run handles. Some workflow fields are defensively parsed extensions rather than declared SDK guarantees.
- [ACP tool calls](https://agentclientprotocol.com/protocol/v1/tool-calls): updates are partial; content may contain text, resources, diffs, or terminal references. `search` is not inherently a web search, and tool titles are descriptive text rather than reliable agent identity.
- [Copilot SDK event scope](https://github.com/github/copilot-sdk/blob/main/docs/features/custom-agents.md#event-types) and the installed `@github/copilot-sdk/dist/generated/session-events.d.ts`: native `subagent.started/completed/failed` include the launching tool id, names, model, and optional terminal usage. Child-originated events have envelope `agentId`; older events may use `data.parentToolCallId`. Child turn/error/abort events must not change the root session.
- Transport matters: Ryco's OpenCode and Copilot implementations use their native SDKs. Cursor and Grok use the shared ACP runtime. Adding ACP-specific handling alone does not repair the SDK paths.

## Changes implemented

1. **Copilot native roster:** map started/completed/failed SDK events to existing shared `task.*` activities. Persist stable launch identity, role, display name, model, description, cancellation/failure, and reported usage. Terminal events remain independently identifiable when the start event is absent.
2. **Copilot root isolation:** recognize child envelopes before updating the active turn, resolving pending parent starts, updating root error state, or retiring root turn authority. Child narration is excluded from the parent answer. Native lifecycle still reaches the Agents roster. Full child transcript correlation is a remaining item below.
3. **Grok and Cursor ACP lifecycle:** use one session-scoped implementation for summary subagent events. Grok now emits the lifecycle it previously omitted. Completion-first streams produce a start and terminal event, duplicate completions are ignored, and late running updates cannot reopen settled children.
4. **ACP identity and result quality:** stop searching shell commands and tool descriptions for delegation keywords. Prefer explicit subagent fields or narrowly identified delegation tools. Carry reported model/role and the actual terminal report instead of repeating the launch label.
5. **Shared tool output:** extract ACP plain strings and typed content, Claude tool-result content, Copilot detailed results, OpenCode output/errors, stdout/stderr, embedded text resources, and explicitly marked structured MCP output. Both progress projection and persisted work-log reconstruction use the same helper. Cumulative progress stays compact; completed output retains the existing bounded persistence path. Binary media is not dumped as text.

These changes use existing rendering surfaces through the shared client runtime; they do not add a separate web/mobile parser or change hosted readiness policy.

## Agents panel follow-up

The desktop Agents surface now opens agent details within the same tab, including legacy deep links. The shared transcript fold assigns tools by explicit agent, parent tool, or provider thread identity and retains their first sequence. Parallel tool lifecycles collapse by tool identity, and messages and tools render in one chronological feed. Command summaries use the main chat's command classifier; exact commands, captured output, exit codes, and tool completion are expandable. The frozen web phone presentation retains its existing panel.

Codex child command snapshots and completed assistant messages now reach the child transcript. OpenCode child tool parts retain their structured input and result without entering the parent turn's item collection. Queued, running, waiting, idle, completed, failed, and interrupted agents have distinct labels. Background status retains monitor classification across sparse updates, ignores delayed terminal-task updates and older attempts, and accepts a newer explicit attempt. Canonical ACP subagent events also contribute to background liveness where no native task lifecycle exists.

Provider silence is not proof of completion. The panel shows the last reported activity time and identifies tools without a completion event; unavailable provider details remain explicitly unavailable. Codex child assistant text currently appears from completed message snapshots, not token-by-token child streaming.

Workflow completion also settles explicitly owned background members on the server, matching the existing client cascade. Ordinary nested agents remain independent.

Validation of the follow-up: 94 focused client tests, 104 focused server tests, and 12 browser checks across AgentsPanel, ThreadWorkspacePanel, and ChatHeader passed. Formatting, lint (existing warnings), typecheck, and production builds passed.
