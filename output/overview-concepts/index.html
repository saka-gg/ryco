Three threads share one worktree note. A thread-scoped note would only reach one of them.

Threadbacklink only
  • Perfect context while you're in it
  • Splinters as soon as a follow-up or review thread opens on the same branch
  • The transcript already is the thread's record
Worktree (workspace)recommended
  • Same unit as everything else in the overview: branch, changes, checks, PR
  • Carries across every thread working on that branch
  • Clean lifecycle: archives, restores and deletes with the workspace via the existing lifecycle plans
  • The main checkout is a workspace too, so local-mode threads still get notes
  • Codebase-wide knowledge doesn't fit, so use pin-to-project for that
Projectpinned only
  • Durable: survives worktree cleanup
  • As a default it becomes a dumping ground, shown in every unrelated worktree
  • Overlaps with AGENTS.md and project preferences for agent-facing knowledge

Contract & storage

  • packages/contracts/src/notes.ts: schema only: { id, worktreeId, projectId, pinned, body, sourceThreadId?, createdAt, updatedAt }
  • Server-owned and keyed by WorktreeId. The main checkout already has one (mainWorkspaceId)
  • Not localStorage: notes must follow you across desktop, web, mobile and Hub

Sync & lifecycle

  • Projected through orchestration into a client-runtime/state/notes domain shared by web and mobile
  • Workspace archive/restore carries notes. The delete plan warns "removes N notes" unless they're pinned
  • Hosted service worker never caches them (node-owned content)

Later

  • "Send to agent" drops a note into the composer
  • An Agent Control read tool, so delegated threads can see worktree notes
  • Notes as timeline bookmarks (concept 5): anchor a note to the commit it was written at
