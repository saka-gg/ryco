# Attachment previews and computer use review

Reviewed 4 October 2026. This is a code and upstream-source review with focused automated tests and a live Electron browser smoke. Native desktop latency, CPU, and memory were not benchmarked.

## Changes implemented

- Clicking a supported document attachment opens Ryco's document viewer. The filename is no longer the download action; Download is separate. This applies to Markdown, text, and PDF attachments. RPC attachments still load only on demand and open after the first click.
- Markdown uses a rendered reader with headings, emphasis, lists, code, and GitHub-style tables. HTML is not executed, remote images are not fetched, and local file links cannot launch another application. Text previews retain the 512 KiB limit and UTF-8/binary checks.
- Agent-created built-in Ryco browser tabs stay hidden or docked in the workspace Browser panel, including when an agent supplies `visible:true` or calls `show`. Those requests do not open a native Ryco Browser window or switch the user's panel. Manual Pop out remains available. External Chrome/Brave/Edge presentation retains its foreground authorization.
- Computer previews now appear beneath the desktop Overview instead of floating over the conversation. A built-in browser thumbnail opens the workspace Browser panel when clicked. Thumbnail capture runs at most once every two seconds, with no overlapping reads, and pauses while the thumbnail is offscreen or the document is hidden. Native preview visibility also follows its position in the Overview scroll area. Closing Overview or hiding a preview does not stop agent work.

The compiled driver has meaningful local patches: cancellation, admission and cleanup checks are not interchangeable with an upstream binary. Startup checks version, native revision and runtime ownership; provisioning checks source and patch provenance. A plain dependency or binary replacement would discard those guarantees.

## Improvements worth doing next

1. **Avoid native fallback screenshots while the live tap is healthy.** The server's one-second preview timer asks the backend to capture a still. The desktop then discards that still if a native frame arrived within 1.5 seconds. This avoids duplicate display, but still spends the capture, validation, base64 and bridge work. Move the health check before capture, scoped to the same thread, turn and exact target. Resume fallback when live frames stop, and preserve the stale-generation fences. This is the strongest concrete performance opportunity found.
2. **Use a shared browser capability interface without merging identity namespaces.** The built-in browser docks well but lacks the driver's transfer/dialog features; the driver is more capable but cannot dock interactively. A Ryco-owned controller interface could share action validation, effect reporting and observation rules while preserving separate targets, profiles and permissions. Frame-aware observation and interaction would expand iframe support. Transfers need explicit workspace bounds and user-visible controls; simply removing the download block is insufficient.
3. **Reduce hidden browser host overhead.** EmbeddedComputerBrowser currently allocates a hidden BrowserWindow for every tab, in addition to each page's WebContentsView, with a 24-tab bound. Consider one retained background host and create detached hosts only for manual Pop out. Measure RSS and renderer CPU with 1, 8 and 24 tabs before adopting it. Test guest destruction, docking, resizing, sign-in popup cancellation and shell reload; savings cannot be inferred from window count alone.
4. **Consolidate the two native controllers incrementally.** ComputerUseRuntime constructs both the older helper-based path and DesktopComputerBeta. They duplicate policy, cancellation, browser guidance and setup concepts. Prefer one authoritative runtime with adapters for compatibility tool names, after a capability matrix and provider/platform migration tests. Do not remove the older route before proving that paired-browser and non-macOS use still work.
5. **Budget and measure preview cost independently from agent observation.** Native preview uses JPEG binary frames while fallback preview takes base64 round trips and allocates Blob URLs in the renderer. Track cold/warm dispatch, observation duration, screenshot/encoding time, queue delay, dropped/coalesced frames, and RSS/CPU. Use latest-frame backpressure for presentation only; never use a cached thumbnail to satisfy model observation or mutation recovery. Keep model screenshots at their required detail.
6. **Qualify platforms and profile-dependent workflows.** Current native macOS behavior and Linux's restricted headless browser path are intentionally different. Add disposable fixtures for iframe navigation, dialogs, uploads/downloads, login popups, renderer crash, interruption and reconnect. Capability claims should follow those checks rather than the upstream platform list.

## Upstream assessment

The official [Cua Driver 0.28.2 release](https://github.com/trycua/cua/releases/tag/cua-driver-rs-v0.28.2) lists fixes for snapshot identity, macOS capture and Hyprland scrolling/text. It is a published stable driver release despite GitHub's pre-release label. Ryco pins its own patched source, so matching the version string does not prove identical behavior to the release binary.

[Synara 0.9.2](https://github.com/Emanuele-web04/synara/releases/tag/v0.9.2) is a relevant follow-up comparison to the port's 0.9.1 baseline. Inspect focused source changes and rebase compatible patches with regression checks; no claim of automatic feature parity or a safe drop-in upgrade is made here.

Electron's [WebContentsView](https://www.electronjs.org/docs/latest/api/web-contents-view) already supplies the native page surface used by Ryco's workspace browser. Keeping that surface and improving the integration is the most direct fit for the requested background workflow.

Recommendation: retain the pinned driver and improve Ryco's integration first. Benchmark the fallback suppression and hidden-host changes before claiming speed or memory gains. A wholesale library replacement is not justified by this review.

## Validation

- Bun 1.4.0; dependencies installed with `bun install --frozen-lockfile`.
- 58 browser tests across attachment previews, computer previews, browser surfaces and ChatView workspace behavior passed. The final native preview visibility change also passed its five focused browser tests.
- 34 focused unit tests passed: 21 web classification/browser-state tests, eight desktop browser/IPC tests, and five server computer-tool tests.
- Web and desktop TS7 typechecks passed. Focused lint returned no errors; the broader changed-file pass reported existing hook/purity warnings in ChatView and ChatOverviewPanel.
- Live Electron browser smoke passed with `visible:true` plus `show`: no native window became visible or focused. Background form input, navigation, cursor, screenshot, stale-reference rejection and stop were exercised against disposable local fixtures.
- Changed files were formatted and `git diff --check` passed. No full repository build, native driver rebuild or native desktop performance benchmark was required for these focused presentation changes.
